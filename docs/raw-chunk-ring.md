# 生チャンクリング（RawChunkRing）— xterm 表示崩れの事後診断

## 目的
「先頭に想定外の1文字が入る」「再描画すると直る」タイプの表示崩れを事後診断する。

エミュレータ（`EmulatedStateBuffer`）はパース済みグリッドしか持たず、**どのバイト位置でチャンクが
切れて届いたか**という境界情報が消えている。一方 xterm 側の崩れは「エスケープシーケンスが
チャンク境界で分断され、その合間にリプレイ注入（`\x1bc`＋スナップショット）が挟まって断片が
孤児化し文字として印字される」形で起きうる（`RawChunkRingTests` で機序を再現済み）。
このリングは生チャンクを境界つきで直近ぶんだけ保持し、後から取り出して突き合わせる。

## 記録される内容
セッション（エミュレータバッファ）ごとに、直近 512K 文字ぶん:

- **チャンク**: 通し番号・UTC時刻・生データ・`PendingAfter`（そのチャンク取り込み直後に
  パーサが未確定のまま保持している分断シーケンス。**非空＝シーケンス途中で終わった容疑チャンク**）
- **マーカー**: `BeginReplay`（注入開始。スナップショット文字数と pending 種付け文字数）/
  `EndReplay` / `Clear` / `Resize`

## 取り出し方
1. セッション一覧: `GET /api/debug/raw-ring` → GUID・エントリ数・表示名のリスト
2. ダンプ取得: `GET /api/debug/raw-ring/{GUID}` → 人間可読テキスト
   （取得と同時に `logs[-dev]\raw-ring\` にもファイル保存される）

また、**エミュレータ再同期（rowsGrew 時の注入）実行のたびに自動でダンプを保存**する
（`[RawRing] 再同期時の生チャンクリングを保存: <path>` がログに出る）。崩れに気づくのが
遅れてリングから証拠が流れるのを防ぐため。保存先は直近20ファイルでローテーション。

## 読み方（崩れが出たとき）
1. 崩れたセッションのダンプを開く（自動保存分 or 手動取得）
2. `**PENDING=...**` の付いたチャンクを探す（＝シーケンス途中で切れたチャンク）
3. その直後に `---- BeginReplay ... ----` マーカーが挟まっていれば、孤児フラグメント仮説が確定。
   `pending種付け=0文字` なのに PENDING 非空、などの不整合があれば防御（`VtParser.Pending` の
   テール種付け）のすり抜けケースが特定できる
4. 何も挟まっていないのに崩れている場合は別因（UTF-8 デコード・JS 側 write 経路等）を疑う

制御文字は `\e` `\r` `\n` `\t` `\a` `\xNN` にエスケープされて出力される。

## 実験モード: リングの実経路再生

`POST /api/debug/raw-ring/{GUID}/replay` で、リングの内容を**ライブ出力と同一の実経路**
（チャンクごとに1回の JS interop = SignalR 配送）・**記録どおりのチャンク境界**で xterm へ再生する。
対象セッションを**前面表示しているブラウザ**で再生される（前面でなければ何も起きない）。

目的は崩れ要因の単離。切り分け表:

| 実験 | データ | 境界 | 経路 | 崩れたら |
|---|---|---|---|---|
| ローカル直書き（scratchpad の再生ページで term.write 直接） | リング | リング通り | なし | データ/境界起因（xterm パーサのバグ） |
| **実経路再生（このモード）** | リング | リング通り | SignalR/interop/terminal.js | **経路起因の決定論的バグ** |
| どちらも崩れない | - | - | - | 非決定論（配送欠落等）を疑う → 連番検知へ |

注意:
- エミュレータ・リングには書かない（記録を汚さない）。再生後の xterm はリング内容になるため、
  **通常表示へ戻すにはセッション切替**（エミュレータからのリプレイ）を行う
- 再生中はライブ出力が書き込みロック待ちになる。**アイドル中のセッションで使う**こと
- 完了ログ: `[RawRingReplay] 実経路リング再生完了: {n}チャンク {n}文字 保持{ms}ms`

## 実装
- リング本体: `TerminalHub.Terminal/RawChunkRing.cs`（UI 非依存・単体テスト可）
- 組み込み: `EmulatedStateBuffer.Append/BeginReplay/EndReplay/Clear/Resize`
- ダンプ保存: `TerminalHub/Services/RawRingDump.cs`（保存先は Program.cs 起動時に設定）
- エンドポイント: `Program.cs`（`/api/debug/raw-ring`）
- テスト: `TerminalHub.Terminal.Tests/RawChunkRingTests.cs`
  （リング動作＋孤児フラグメント現象の再現・防御経路の回帰）
