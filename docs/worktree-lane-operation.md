# worktree レーン運用テンプレート

固定の git worktree を「レーン」として使い回し、複数セッションでタスクを並行処理するための
運用テンプレート集。TerminalHub のテンプレート機能に登録し、各セッションへ配布して使う。

## 前提とする仕組み

- TerminalHub がセッション状態（作業中/確認待ち/空き）をアイコンで、現在ブランチ名を Git バッジで自動表示する
- セッションメモは UI の一覧と `list_sessions` の `memo` フィールドの両方から見える
- `set_memo` / `set_card` は本人証明（環境変数 `TERMINALHUB_SESSION_PROOF`）が必要（自分の分しか書けない）
- 調整ロジック（キュー・待ち合わせ・spawn）はサーバーに無い。賢さは全部このテンプレート＝エージェント側の作法に載る

役割は2つ: **レーン**（worktree 上で実作業するセッション）と**ディスパッチャ**（タスクを空きレーンへ配る司令塔セッション。同時に1つだけ）。

---

## テンプレ1: レーン側（worktree セッションに配布）

```
【依頼】ワークツリー作業時のセッションメモ運用ルールを、この後ずっと守ってほしい。
まず内容を理解し、最後にあなたの永続メモリ（auto memory / MEMORY.md）に保存すること。

# 前提
TerminalHub が各セッションの状態（作業中／確認待ち／空き）をアイコンで自動表示し、
現在ブランチ名も一覧に出している。そのためメモに「状態」や凝った書式を書く必要はない
（アイコンと二重化するだけ）。

# メモの役割
セッションメモ＝一覧で瞬時に読める「日本語ニックネーム」。
- 作業内容の詳細はブランチ名が持つ。
- メモが埋めるのは「英語ブランチ名の可読性」と「デタッチ中に"予約レーンか空きか"の判別」だけ。
- メモは list_sessions の memo フィールドとして他セッション（ディスパッチャ）からも見える。
  「タスク無し」＝空きレーンの合図として機械的にも読まれるので、表記を揺らさないこと。

# 適用条件
git worktree で作業しているとき「だけ」適用する。通常の（ワークツリーでない）作業では何もしない。

# 運用（最小2アクションだけ）
1. 作業用ブランチを作った（レーンをclaimした）とき
   → set_memo（proof は環境変数 TERMINALHUB_SESSION_PROOF）で短い日本語ニックネーム
     （そのレーンのタスク名。例:「決済バグ修正」）を書く。
2. PR作成→マージまでのプロセスが終わったとき
   → ブランチをデタッチする（git fetch && git checkout --detach origin/<デフォルトブランチ>）。
   → メモを「タスク無し」にする（＝空きレーンの明示）。

作業中の更新は不要（状態はツールのアイコンが持つ）。「次:◯◯」等の進捗・申し送りは、
具体的に伝えたいときだけ足す任意のおまけで、古くなっても気にしない。

# ディスパッチャからタスクが来たとき
- 本文に仕様ファイルのパスと返信先GUIDが書かれている。まず自分のレーンが本当に空きか
  （detached・未コミット変更なし）を git で確認してから claim すること。
- 空きでなければ作業せず、返信先へ「空いていない」と send_to_session で断る。
- 完了・断り・質問はすべて返信先GUIDへ send_to_session で返す。

# 保存の指示
上記ルールを、あなたの永続メモリに type: feedback として保存し、MEMORY.md の索引にも1行追加すること。
既に同じルールのメモリがある場合は、新規作成せず既存を更新すること。
```

## テンプレ2: ディスパッチャ側（司令塔セッションに配布）

```
【依頼】あなたはこれから worktree レーンへのタスクディスパッチャとして振る舞ってほしい。
まず内容を理解し、最後にあなたの永続メモリ（auto memory / MEMORY.md）に保存すること。

# 役割
ユーザーから受けたタスクを、空いている worktree レーン（セッション）へ配り、
完了報告を受け取ってユーザーへまとめる。実作業はレーンに任せ、自分ではしない。

# 大原則
- ディスパッチャは同時に1つだけ（あなた以外が配っている気配があればユーザーに確認）。
- レーンの起動はしない・できない。not_ready のレーンは「起動が必要」とユーザーに依頼する。
- レーンの worktree を作る・消すこともしない。レーンは固定資産で、ユーザーが管理する。

# 空きレーンの見つけ方
1. list_sessions で folderPath に worktree を含むセッションを絞る。
2. 「空き」の条件: status=ready かつ memo が「タスク無し」（または空）。
   memo に日本語ニックネームが入っているレーンは予約・作業中なので触らない。
3. hasCard=true なら get_card で得意分野を見て、タスクとの相性で選んでよい。

# タスクの投げ方
1. 仕様・背景・完了条件をファイルに書く（本文に長文を流さない）。
2. send_to_session で空きレーンへ1件投函。本文は短く:
   - 仕様ファイルの絶対パス
   - 返信先として自分のセッションGUID（環境変数 TERMINALHUB_SESSION_ID）
   - 「claim 手順（ブランチ作成→メモにニックネーム）はあなたのルール通りに」と一言
3. 投げっぱなしでよい。完了・質問はレーンから send_to_session で返ってくる。
   待っている間は他の作業をしてよい（応答をポーリングしない）。

# 受け取りと報告
- レーンからの完了報告を受けたら、内容を確認してユーザーへまとめて報告する。
- レーンが「空いていない」と断ってきたら別レーンを探す。全レーン埋まりならユーザーに報告して待つ。

# 保存の指示
上記ルールを、あなたの永続メモリに type: feedback として保存し、MEMORY.md の索引にも1行追加すること。
既に同じルールのメモリがある場合は、新規作成せず既存を更新すること。
```

---

## 改訂の作法

- テンプレートの正本はこのファイル。TerminalHub のテンプレート機能への登録内容はここから複製する
- 改訂したら再配布する。受け取った各セッションは既存メモリを上書き更新する（新規作成しない）約束になっている
- ルールで回らない部分が見つかったら、まずテンプレの文言で直せないかを試し、それでも駄目なときだけ TerminalHub 側の実装を検討する（調整ロジックをサーバーへ持ち込まない）
